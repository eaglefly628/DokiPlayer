# 如何测试 DokiWorlds 故事

更新：2026-10-21。本手册来自实际页面和新手引导，随探索修订。

## 评什么

DokiWorlds 是框架，每个故事是框架上的独立体验。分别记录框架可靠性、交互与画面，以及故事的因果、人物、节奏、选择反馈和收束。平台故障影响体验时记录影响，但不直接断定是剧本缺陷。AI 判断必须附证据和观察范围；评分标准目前是草案。

## 进入旅程

1. 打开 https://test.aimeng.ai/，访问密码由用户在页面输入。
2. 点击故事体验入口；需要账号时由用户完成登录和用户许可确认。
3. 选择专用测试存档。存档额度按账号共享；本次免费账号为2个。额度满时暂停交给用户处理。永久删除会连同进度、对话和备份一并删除，程序不自动确认删除。
4. 鬼故事已验证：开始新的长夜 → 选择存档槽 → 新建 → 等待世界资源。
5. 开场漫画：左下角“点击揭示下一格”逐格推进，记录每格内容；最后点击“点击开始行动，跟随高亮完成第一步。”；章节页点击“继续旅程”。不要为了省点击跳过序章，序章是故事证据。
6. 正式界面出现角色对话、行动牌、精力等；先读“卡牌怎么玩”。登录和菜单不是可评分的故事正文。

## 从引导建立知识

当前玩法手册7个主题已全部逐项阅读，原文保存在 `knowledge/sources/tutorial-2026-10-21.json`。阅读完成与出牌实践是不同记录，不能把看过教程当成已验证所有机制。提炼的跨故事候选规则见 `knowledge/framework.json`，鬼故事线索见 `knowledge/ghost-story.json`。

## 每一步怎么理解和选择

1. 读当前目标、地点、人物、任务、时间、精力和压力。将事实、人物说法、行动预测分开。
2. 读可用牌的类型、描述、消耗、检定概率和风险。推荐与稀有度不等于最优选择。
3. 给出简短行动依据和预期反馈。先完成必要前置，再推进目标；避免仅反复对话却误以为已移动。
4. 点击一张牌即提交，无二次确认。等结算、回应和补牌完成后再行动。
5. 对比行动前后：叙事是否承接、规则是否生效、资源是否一致、人物是否记住信息。失败有消耗不一定是问题，先看牌面规则。
6. 证据不够时记为问题待验证，提出一次可执行的验证行动。不要把单次失败或未访问分支当成全局问题。

## 在线异常

已观察到“AI回应未通过校验”和“AI回应超时”，并切换为本地回应。用户经验：左上角辅助工具中选择较快模型，再重试在线回应；恢复效果待实测。记录失败提示、前后模型、时间、钻石成本和是否恢复。不把重试消耗混入剧情行动消耗。

## 输出与知识更新

每次保存截图、页面文字、可选行动、所选行动、简短理由、预期、实际结果、错误与最终停止原因。新规则附来源、日期、适用故事、验证程度；反例保留。知识状态用 tutorial_stated / play_verified / user_reported / hypothesis 区分。

故事评审与框架评审分开输出；无截图不评画面，未见结局不评收束。当前只验证了鬼故事开局与教程，不代表完成全剧或覆盖其他故事。未来应通过多路线、多次运行和人工校准提高判断稳定性。
